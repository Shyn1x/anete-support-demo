## Подтверждённые причины проблем

1. Небольшой прежний набор товарных фактов не покрывал ассортимент. Отсутствие товара в нём нельзя трактовать как отсутствие в магазине.
2. Простое совпадение слов давало нерелевантные результаты: корм смешивался с добавками, краски — с бумагой и вспомогательными средствами, палатки — с ремонтными деталями. Добавлены категории и фильтры. Это ограниченный поиск по названиям, категориям и словарю RU/LV/EN, не семантический поиск по всем описаниям.
3. Большой каталог HobbySet нельзя полностью читать и проверять при каждом запросе Worker. Поиск перенесён в подготовленные при сборке списки совпадений и небольшие порции товаров. Это снижает вычисления; производственную задержку и CPU всё ещё нужно измерить после разрешённой публикации.
4. При переходе «список → второй вариант» требовалось сохранять конкретные ссылки, а не угадывать товар по старой истории. Теперь контекст содержит до трёх проверенных ссылок только своего магазина. Новая ссылка заменяет старый выбор; новая модель не наследует его характеристики.
5. Проверки нашли английские запросы, пропускавшиеся из-за служебных слов, и латышский вопрос о безопасности спальника, проходивший через товарную ветку. Исправлены обе ветки.
6. Публичные страницы нестабильны: несколько последовательных проверок дали таймауты у разных магазинов. Последняя отдельная проверка небольшого публичного поиска Anete также завершилась таймаутом. Эти результаты сохранены, а не объявлены успешными.

## Бюджет и безопасность

- Проверка допуска предшествует внешнему чтению. Внутренний одноразовый билет привязан к клиенту и живёт 30 секунд.
- Денежный резерв создаётся только после пригодного чтения и проверки размера запроса ИИ; одно сообщение учитывается один раз. Повторный/чужой/просроченный билет отклоняется. Это проверено также в workerd с SQLite.
- Существующие лимиты, сумма резерва `$0.01`, namespace `experiment-v1` и счётчики сохранены. Новый день не сбрасывает общий резерв.
- Список названий, пустой поиск и неудачное чтение не вызывают OpenAI. При исчерпании бюджета остаётся режим источников.
- Каталоги доступны через внутренний ASSETS binding; публичные пути JSON остаются закрыты. Клиентские сборки содержат только каталог своего магазина. Проверка URL не разрешает чужие хосты, credentials или произвольные редиректы.
- Приватные данные пользователя, cookies и ключи не отправляются магазинам. Потенциально чувствительные обращения отсеиваются до поиска. Источники считаются недоверенными данными, не инструкциями.
- Секреты в клиентские сборки не добавлялись; реальные персональные данные и платежи в тестах не использовались.

## Обновление ZIP-копии пользователя

После сохранения этой ветки используйте полный неизменяемый SHA коммита из сообщения о выпуске:

```powershell
Set-Location 'C:\Users\shyn1\support-demo-20261015-214857\anete-support-demo-main' -ErrorAction Stop
node .\scripts\prepare-live-audit-update.mjs --release 'FULL_40_CHARACTER_COMMIT_SHA'
if ($LASTEXITCODE -ne 0) { throw 'Проверка не пройдена. Обновление остановлено.' }
```

Этот существующий обновлятор проверяет Git blob hashes, переносит UTF-8 байты без ручного редактирования PowerShell, тестирует отдельную staging-копию, сохраняет резервные копии и проверяет неизменность отчётов. Зависимости не менялись. Он **не публикует** Workers и не вызывает модель. Не редактировать кириллицу через `Set-Content` и не заменять отчёты тестов.

Публикация — отдельный согласованный шаг через существующий `publish-live-audit.mjs` по созданной receipt. Для этого выпуска нужен полный режим шести Workers, **owner первым**: клиенты используют новый внутренний вид запроса к общему guard. Режим `--owner-only` не подходит. Существующие AI/CATALOG-флаги в прочитанной публичной конфигурации шести демо уже включены; новые секреты/лимиты не нужны. До явного разрешения публикацию не выполнять.

После публикации сначала бесплатно проверить `/api/config`: `catalogRevision` должен стать `retrieval-v1`, доступ и изоляция — сохраниться. Затем отдельно согласовать число платных проверок и предел расходов. Нельзя считать неизменённые 27/50 прошлых сценариев проверкой нового выпуска.
