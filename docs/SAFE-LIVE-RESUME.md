# Безопасное обновление ZIP-копии и завершение живой проверки

Папка владельца: `C:\Users\shyn1\support-demo-20261015-214857\anete-support-demo-main`.
Требуется Node.js 22+ и существующие зависимости проекта. Git на компьютере не нужен.

## 1. Подготовка, без публикации и расходов OpenAI

Используйте один фиксированный commit SHA рабочей ветки, предоставленный вместе с обновлением. Не `main`, не изменяемую ссылку на ветку. Скачайте `scripts/prepare-live-audit-update.mjs` по этому SHA через `Invoke-WebRequest -OutFile` и сверьте SHA-256 файла с указанным в передаче. Не используйте `Get-Content | Set-Content`, вставку русского исходника в PowerShell или ручную замену кодировок.

Из папки проекта:

```powershell
node "ПУТЬ_К_СКАЧАННОМУ_prepare-live-audit-update.mjs" --release COMMIT_SHA
```

Подготовщик получает дерево фиксированного релиза, проверяет Git blob SHA каждого скачанного файла, сохраняет байты без перекодирования, запускает Node-тесты, сборку и настоящий локальный workerd с SQLite. Установленные зависимости должны соответствовать релизу, автоматической установки нет. При отсутствии зависимости или провале проверки обновление не применяется. Проверки запускаются в отдельной staging-папке. При ошибке копирования частично применённые файлы восстанавливаются из резервной копии.

На этом шаге **нет** публикации, входа в Cloudflare, запросов OpenAI или изменения конфигураций. `wrangler.jsonc`, `deploy/clients/*`, файлы секретов и весь `reports/` исключены из установки. Старый исходный код сохраняется в `.audit-updates/<время>/backup`. Подготовщик печатает путь к `receipt.json` с точным релизом и хешами файлов.

После успешной подготовки:

```powershell
node .\scripts\run-live-50.mjs .\reports\live-50.json
```

Эта команда теперь делает **только офлайн-аудит**. Она не просит пароли, не вызывает модель и не меняет отчёт. Увидите число оставшихся сценариев, подозрительные строки и случаи `answer_validation`. При повреждённой кодировке отчёт не исправляется автоматически. Сохраните исходник и `live-50-backup.json`, пришлите актуальный исходный JSON для разбора. Строка с несовпадающим вопросом не становится успешной и не попадает в автоматический повтор.

## 2. Публикация — только после отдельного согласия

Не запускайте на шаге подготовки. После разбора отчёта и разрешения владельца:

```powershell
$receipt = Get-ChildItem .\.audit-updates\*\receipt.json | Sort-Object LastWriteTime -Descending | Select-Object -First 1
if (-not $receipt) { throw 'Validated update receipt not found' }
node .\scripts\publish-live-audit.mjs --receipt $receipt.FullName --confirm-publish
```

Скрипт сначала проверяет, что исходники не менялись после подготовки. Пересобирает клиентские файлы, сверяет имена шести Workers, существующие entrypoints, TENANT_ID, класс/привязку BudgetGuard и неизменную миграцию v1. Компилирует все конфигурации с `--dry-run` и проверяет наличие существующих Workers через `wrangler versions list` **до первой публикации**. При ошибке или неверном аккаунте останавливается. Никаких `--yes`, новых временных аккаунтов, платных планов, ротации секретов или сбросов.

Публикуется Anete (он также владеет общим BudgetGuard), затем пять отдельных магазинов. Частичная публикация возможна при сетевой/провайдерной ошибке — скрипт останавливается на первой, не скрывает её и не обещает атомарный откат шести Workers. До восстановления целого релиза живой прогон запускать нельзя.

Временные конфигурации сохраняют `keep_vars` и TENANT_ID, но **не переобъявляют** дневной/общий бюджет или AI-флаги из старой ZIP-копии. `--keep-vars --strict` сохраняет текущие dashboard vars и секреты. Действующие счётчики/имена/пространства Durable Objects не меняются. Скрипт не включает ранее выключенный ИИ: если он отключён, последующая проверка конфигурации остановит прогон.

## 3. Оставшиеся проверки — отдельное разрешение на API

Публикация не равна согласию на расходы API. После отдельного разрешения на максимум 23 дополнительных запроса:

```powershell
node .\scripts\run-live-50.mjs --report .\reports\live-50.json --run --allow-paid --max-requests 23
```

Все незавершённые магазины предварительно должны сообщить `context-v2`, включённый разговорный режим и `auditRevision: safe-resume-v1`. После этого вводятся **пароли демо** скрытым вводом. API-ключ не требуется и не вводится. Не вставляйте пароли в чат или аргументы команд.

Прогон создаёт **новый** `reports/live-50-resume-<время>.json`, сохраняя старые строки и SHA-256 исходного отчёта. Старый `live-50.json` и backup остаются как были. Завершённые, pending и ambiguous ID не повторяются. Исторические провалы не пересчитываются. Перед новой отправкой в новый отчёт записываются pending-состояние и хеши точного UTF-8 тела и вопроса; секретов/cookies там нет.

Не более 23 chat-запросов всего за запуск, без автоматических повторов. Существующие дневной/общий резерв, частотные ограничения и сообщения об отказах по-прежнему останавливают прогон. После первого отказа валидации или неоднозначного сетевого результата нужно разобрать причину, а не повышать лимит. Если лимит исчерпан, ждать обычного перехода суток UTC; общий предел не сбрасывать.

Для следующего разрешённого продолжения используйте последний resume-файл как **вход**, сохраняя цепочку предыдущих файлов. Не начинайте снова с первоначального 27-строчного отчёта, иначе новые завершённые ID из прошлой сессии не будут видны. При аварийном закрытии окна может остаться `reports/.live-50.lock`: не удаляйте его, пока не убедились, что старый процесс Node завершён.

Два сомнительных случая и другие провалы повторяются только отдельным согласованным тестом после диагностики и одобрения дополнительных расходов, не этим автоматическим продолжением.

## Бюджет и критерий готовности

До USD 0.23 **дополнительного резерва приложения** для 23 потенциальных вызовов, без увеличения действующих лимитов. Это не счёт OpenAI. Точное число ожидаемых AI-сценариев вычисляется офлайн по настоящему отчёту. Предположительные расходы по токенам и источники цен — в техническом обзоре.

Нужно закончить оставшиеся сценарии, разобрать четыре исходных провала, проверить ответы человеком и отдельно проверить ссылки/вход с телефона. Автоматический pass не заменяет проверку источников и естественности речи. Пока эта версия подготовлена для контролируемой проверки владельцем, не объявлена готовой клиентской системой.
