## Подготовленное изменение

В buyer-v8 вместо воспроизведения цитат или объекта с динамическими полями используется простой протокол ссылок на фрагменты:

1. Сервер выбирает буквальные исходные цитаты, максимум 6 на товар, как раньше.
2. Каждому фрагменту выдаётся короткий локальный идентификатор, например `evidence_0_0`, который связан с конкретным ID товара и точной цитатой. Сами цитаты и связь видны модели в прочитанных фактах.
3. Модель возвращает массив таких строк из разрешённого enum. Схема содержит только object/array/string, enum, properties, required и additionalProperties:false. Нет anyOf, nullable-объектов, динамических полей, minItems/maxItems.
4. Сервер отклоняет неизвестные, смешанные, повторные ссылки и ссылки чужого выбранному ID товара. Каждому выбранному товару требуется собственное подтверждение. Затем ID фрагмента разрешается в серверную исходную цитату и проходят все прежние независимые проверки точного вхождения, чисел, языка, материалов, обещаний и персональных данных.
5. Это новый явно заданный протокол ссылок на источник, а не исправление выдуманной моделью цитаты. Старые форматы подставных тестов всё ещё проходят прежние строгие проверки. Правильная ссылка на источник не разрешает неподтверждённые утверждения.

Динамические текстовые enum цитат и union не нужны для этого протокола. Удаление ограничений длины массива из схемы не убирает серверный предел 3 и проверку непустого/полного набора. Размер запроса, ограничение 450 выходных токенов, модель gpt-4.1-mini, одна попытка без retry, лимиты, секреты и namespace остаются прежними.

Проверена [официальная документация OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) и [gpt-4.1-mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini) 22.10.2026. Документация описывает базовые типы/enum и поддержку Structured Outputs этой моделью. Она также описывает более сложные конструкции, поэтому только по чтению документации невозможно установить точный отвергнутый элемент старого запроса. Упрощение — подготовленное исправление совместимости, **не доказанная живая успешность buyer-v8**.
