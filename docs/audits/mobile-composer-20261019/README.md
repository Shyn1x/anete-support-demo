# Поле ввода на мобильном экране

Причина: фиксированная высота `.chat-shell`, минимальная высота ленты сообщений и несжимаемые элементы управления вместе превышали доступную высоту. `overflow:hidden` обрезал поле и нижнюю подсказку. Фокус мог прокрутить скрытую часть внутри карточки и временно показать поле, но не исправлял начальное состояние.

Исправление только при ширине до 720 px: карточка имеет автоматическую высоту; сообщения ограничены 50svh без обязательной минимальной высоты; подсказки не сжимаются. Поле и нижняя подпись остаются в обычном потоке страницы. Транскрипт по-прежнему можно прокручивать, а до самого поля можно долистать страницу. Десктопные правила не изменены. Сборка обновляет hash ссылки на CSS на основной странице и странице демо.

## Проверено

- Chrome 155 headless с мобильным viewport, ширины 320/375/390/430 px, высота 844 px; все 6 магазинов и RU/LV/EN.
- 72 начальных состояния без фокуса и 72 состояния с длинным диалогом, раскрытыми контактами и превью вложения: поле/нижняя подпись внутри карточки, горизонтального переполнения нет.
- 48 дополнительных состояний при высоте 640 px, включая увеличенный текст/кнопки, без обрезания.
- 12 геометрий при 1024/1440 px полностью совпали с исходными.
- 2137/2137 обычных Node-тестов. Основной сайт и пять клиентских артефактов собраны.
- Ни одного платного запроса. Тест использует настоящий HTML/CSS и браузерный bundle из репозитория, подставляет только публичную конфигурацию; chat/media-запросы запрещены.

[Снимок 390×844 до фокуса](390x844.webp). [Измерения до и после](geometry.json).

Это локальная проверка подготовленного обновления, а не снимок уже опубликованного Worker. Нативная клавиатура физического Android не проверялась: уменьшение viewport до 420 px — лишь приближение. На Cloudflare ничего не опубликовано.

Для повторения оператором с установленным Playwright: сначала `node scripts/check-mobile-composer.mjs --baseline`, затем `node scripts/check-mobile-composer.mjs`. При необходимости задать `PLAYWRIGHT_MODULE` (путь к index.mjs установленного пакета) и `PLAYWRIGHT_CHROME` (исполняемый файл официального Chrome/headless-shell). Новых зависимостей проекта, подписок или изменений лимитов нет. Отчёты теста пишутся только в `reports/mobile-composer-20261019/`.
