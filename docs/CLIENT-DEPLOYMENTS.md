# Отдельные клиентские демо

## Что подготовлено

Пять конфигураций в `deploy/clients/`: rotallieta, bariba, hobbyset, apavi40plus, celotajs. Каждая создаёт отдельное приложение Cloudflare с собственным адресом workers.dev, паролем и секретом сессий. Адреса становятся действующими только после успешной публикации; брать их из вывода Cloudflare, не выдавать предполагаемые URL за готовые.

`TENANT_ID` задаётся на сервере. Смена `?shop=`, `?tenant=`, дублированные параметры и прямые обращения к API другого магазина отклоняются. Каталог, QA, остаток бюджета и исходные модули фронтенда не обслуживаются клиентским приложением. Сессия привязана к магазину и точному адресу; отдельные cookies не передаются соседним поддоменам.

В клиентском чате остаются только ссылки на источники и контакты его магазина. Сам браузер не запрещает посетителю открыть произвольный другой сайт: защита обеспечивает недоступность наших других демо без соответствующего пароля. Публичный GitHub содержит код и названия магазинов, но не пароли или ключи. Конфиденциальность кода и состава клиентов потребует отдельного решения о приватном репозитории.

Каталог на основном сайте требует пароль владельца. Переход ведёт на форму входа, после входа каталог открывается. Из-за новой привязки сессий прежний вход потребуется повторить один раз. Справочный режим без пароля разрешён только у основного локального стенда; отдельное клиентское приложение без пароля не работает даже с выключенным ИИ.

## Общий бюджет

Во всех пяти конфигурациях `GUARD` ссылается через `script_name: anete-support-demo` на существующий `BudgetGuard`. ID остаётся `experiment-v1`. Отдельных локальных бюджетов, миграций или сбросов не создаётся. Суточный и общий пределы продолжает определять основной объект. Не заменять привязку локальной и не удалять исходный Worker.

Проверено по документации Cloudflare:
- https://developers.cloudflare.com/workers/wrangler/configuration/
- https://developers.cloudflare.com/durable-objects/reference/environments/

## Публикация с компьютера владельца

Нужно один раз авторизоваться в Cloudflare. Ключ API вводить только в своём терминале или как Secret в Cloudflare. Пароли и ключи не отправлять в чат, файлы репозитория, команды с сохранением в истории или скриншоты.

1. Скачать актуальный репозиторий и выполнить `npm ci` (Node 22+).
2. Выполнить `npx wrangler login` и подтвердить доступ в своём браузере.
3. В PowerShell безопасно считать ключ в переменную процесса:

```powershell
$apiInput = Read-Host 'OpenAI API key' -AsSecureString
$env:OPENAI_API_KEY = [System.Net.NetworkCredential]::new('', $apiInput).Password
npm run deploy:clients
Remove-Item Env:OPENAI_API_KEY
Remove-Variable apiInput
```

Скрипт собирает пять сайтов, публикует каждый сначала с выключенным ИИ, создаёт отдельные случайные пароль и секрет сессий, загружает секреты через stdin и затем включает ИИ. После каждого успешного приложения выводит пароль только в локальный терминал. Сохранить в менеджере паролей. Не перенаправлять вывод в публичный лог. Повторный запуск заменяет пароли: использовать скрипт для первичного развёртывания; дальнейшие обычные обновления не требуют новых секретов.

Для существующего клиента: `npm run build:clients`, затем `npx wrangler deploy --config deploy/clients/bariba.json --var AI_ENABLED:true`. Не выполнять скрипт первичной установки повторно без намерения заменить все клиентские пароли. Если первичная установка остановилась, уже выведенные пароли остаются у завершённых приложений; продолжение/повтор согласовать с владельцем, чтобы не потерять доступ.

Если уже доступна панель Cloudflare: подключить тот же GitHub-репозиторий отдельно для каждого клиента. Build command: `npm run build:clients`. Deploy command, например: `npx wrangler deploy --config deploy/clients/bariba.json`. Добавить Runtime Secrets `DEMO_PASSWORD`, `SESSION_SECRET` (32+ символов), `OPENAI_API_KEY`, каждый пароль и SESSION_SECRET должны отличаться от остальных. Включить runtime `AI_ENABLED=true` только после настройки секретов. Не добавлять секреты в Build Variables. При последующих сборках проверить, что включение AI не перезаписано исходным `AI_ENABLED=false`.

## Перед рассылкой

Пять приложений необходимо реально опубликовать и проверить, затем заменить ссылки в `docs/outreach/FIVE-DRAFTS.md` на подтверждённые адреса. Проверить на каждом вход своим паролем, отказ чужому паролю, ответ на один вымышленный вопрос и недоступность `/demos`, `/usage`, `/qa`, чужого `?shop=`. Не звонить и не отправлять сообщения в магазины при проверке.

Дизайн: убраны рекламные лозунги; заголовок — название магазина, описание — темы поддержки. Демо и отсутствие доступа к реальным заказам обозначены явно.

## Результаты проверки 15.10.2026

697 Node-тестов и 7 проверок workerd пройдены. Новые проверки охватывают пять tenant-ограничений, независимые пароли, привязку сессии к адресу и магазину, закрытие каталога и диагностики, выбор магазина сервером на чистом адресе и общую SQLite-область бюджета между приложениями. Сборки пяти клиентских сайтов проверены отдельно; Wrangler dry-run подтвердил внешнюю привязку к BudgetGuard исходного приложения. Платных OpenAI-вызовов не выполнялось.

Подготовка кода не означает публикацию отдельных приложений или создание их рабочих паролей. На момент подготовки необходима авторизация Cloudflare. Секреты генерируются и устанавливаются только при фактическом первичном развёртывании.
