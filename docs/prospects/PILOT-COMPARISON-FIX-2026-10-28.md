## Воспроизведённые ошибки защиты

До исправления локально отклонялись три корректные формулировки на тех же сохранённых исходных товарах:

1. `Both monitors weigh 8.5 kg.` — числовой фильтр не мог привязать общее утверждение сразу к двум товарам, даже когда у обоих есть явный `Svars: 8.500000 kg`.
2. `Both yarns contain wool.` — та же проблема с общей подтверждённой составляющей двух пряж.
3. Дословные длинные названия двух удилищ с `2.70m`, `3-18g`, `10-30g` считались отдельными утверждениями об измерениях, хотя ответ сообщал только материал и оставлял массу неизвестной.

Это доказанные классы ложных отказов, согласующиеся с наблюдаемыми причинами, но не восстановление отсутствующего текста ИИ.

## Изменения pilot-buyer-v3

- Общее утверждение с «оба/both/abi/abas» проверяется **отдельно по каждому** источнику. Два разных веса не объединяются; компонент, имеющийся только в одной пряже, не становится общим. Для общего числового утверждения обязательно название свойства: голое число из теста приманки не принимается за массу.
- Точные полные названия моделей с измерениями временно заменяются серверными метками при анализе текста. Числа внутри имени не превращаются в новое утверждение о свойствах. Название без явных измерений остаётся видимым проверке материалов. Голые значения вроде названия `50 g` не маскируются. Исходный ответ, проверка всех чисел и источники не переписываются.
- Сохраняется привязка к первому/второму товару и точному имени. Противоречащие друг другу имя и порядковое обозначение отклоняются. Короткие неуникальные имена не угадываются. Для разных характеристик запрашиваются отдельные предложения.
- В безопасный резервный ответ новых preview-магазинов добавлен строгий разбор полного состава пряжи: только известные буквальные компоненты, полный итог 100%, без неподтверждённых квалификаций и конфликтующих строк. Для исходной пары Dzijas доступны 100% шерсть и 75% шерсть / 25% полиамид. Неизвестный компонент или отдельный технический `Material` запрещает такое извлечение. Это не использование отклонённой генерации и не подмена `conversational=true`.
- В распознавании вопроса о весе учтены латышские формы `svars/svaru/svara/svaram/svarā`.
- `validationDetail` теперь может содержать только ограниченные безопасные коды: `product_subject_unbound`, `measurement_not_in_product`, `measurement_role_mismatch`, `fibre_not_in_product`, `fibre_percentage_mismatch`. Текст, числа и любые персональные данные отклонённой генерации туда не копируются.
- Wire JSON Schema, число запросов к модели, токеновый предел, источник цитат и финансовая защита не расширены. Шесть старых демо не публикуются.

Это ограниченные предметные проверки, а не обещание общего семантического доказательства любой свободной формулировки.
