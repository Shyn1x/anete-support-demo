# Исправление чтения авторизации Wrangler

На компьютере пользователя 34/34 workerd-теста прошли. Затем publisher остановился с `Could not read local Wrangler authentication safely`, до проверки целей и первой публикации. По порядку кода на этом этапе не создаются отметки публикации/платной партии и не запускаются платные запросы.

Причина воспроизведена на установленном Wrangler 4.151.0 с **вымышленным** `CLOUDFLARE_API_TOKEN`, без обращения к провайдеру: `auth token --json` завершался с кодом 0, но при `WRANGLER_LOG=error` stdout был пуст. Этот обработчик использует `logger.log`, в отличие от `whoami --json`, использующего `logger.json`.

Исправлено окружение дочернего CLI: для захваченного stdout установлен уровень `log`, для обычных команд сохранён `error`. Захваченные stdout/stderr не выводятся в терминал. `WRANGLER_WRITE_LOGS=false` принудительно отключает файловые журналы Wrangler для этих дочерних процессов. Это важно: исходный logger пишет сообщения в свой debug-журнал до фильтра уровня. Предыдущий вызов мог оставить токен в **локальном журнале Wrangler**; его не следует прикладывать к диагностике. Само по себе это не свидетельствует о передаче токена третьим лицам или утечке через скриншот.

Новый регрессионный тест запускает настоящий бинарный CLI с вымышленным токеном и временной папкой журналов: JSON успешно разобран, значение не напечатано, журналов не создано. Неверные/неоднозначные аккаунты, другие поддомены и существующие Workers по-прежнему останавливают операцию.

`continue-pilots-auth.ps1` применяется только к исходной ZIP-копии `Lomenti-pilots-4cdf77d9a70a`. Он:

- до изменений проверяет отсутствие `publication.json` и отметки живой партии;
- требует точный SHA-256 исходного publisher;
- скачивает новый publisher по конкретному коммиту, сверяет SHA-256 и сохраняет его байты без PowerShell-перекодирования;
- сохраняет исходный файл отдельно и заменяет только `scripts/publish-pilots.mjs`;
- не переустанавливает зависимости и не повторяет полный набор проверок;
- проверяет синтаксис, затем предлагает скрытый ввод существующего ключа и продолжает ранее согласованную публикацию/живой прогон с теми же ограничениями;
- при наличии старта публикации, иной версии файла или следов предыдущего применения останавливается без удаления отметок.

Существующие Worker-конфигурации, отчёты и финансовые лимиты не редактируются. Сам PowerShell recovery проверен статически, а логика publisher — автоматическими тестами; запуск recovery на Windows пользователя ещё не выполнен. Подготовка этого исправления не публиковала Workers и не делала платных запросов.
