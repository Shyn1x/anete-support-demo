# Запуск новой пятёрки с компьютера владельца

Публикация новых пяти демо и один прогон 50 запросов согласованы пользователем 26 октября 2026. Максимум внутреннего резерва — $0.50 при прежнем резерве $0.01 на попытку. Общие и дневные лимиты не повышаются. Это не изменение разрешений для рассылки, подписок или других расходов.

В облачном браузере Google принял пароль и двухэтапное подтверждение, но Cloudflare вернул `Unable to sign in`. Вход в Cloudflare не подтверждён. Никаких удалённых публикаций или платных тестов при подготовке этого способа не выполнялось.

## Подготовленный путь

`scripts/start-pilots.ps1 -Release <immutable-commit-sha>`:

1. Проверяет Node.js 22+, постоянные отметки партии и закрывает доступ к локальной приватной папке для унаследованных пользователей через Windows ACL.
2. Скачивает ZIP конкретного коммита в новую папку пользователя. Старый распакованный проект, его конфигурация, отчёты и зависимости не редактируются.
3. Устанавливает зависимости из lockfile, запускает весь Node-набор и workerd-тесты. До их успешного завершения публикации нет.
4. Использует существующий `OPENAI_API_KEY` в окружении, либо предлагает скрытый локальный ввод. Значение не пишется в историю команд, исходники или файл с паролями. После завершения исходное окружение восстанавливается.
5. Запускает `publish-pilots.mjs --publish-and-test`. Если Wrangler не авторизован, открывается обычный браузер компьютера для входа в Cloudflare.

Publisher выбирает только однозначный существующий аккаунт, проверяет его workers.dev-поддомен `fshyn1x`, существующий `BudgetGuard` владельца и отсутствие всех пяти новых Workers. Если хотя бы один уже существует, доступ неясен или привязка отличается, он останавливается до публикации. Существующий Worker не перезаписывается и его пароли не ротируются.

После сборки и пяти dry-run каждый новый Worker сначала публикуется с выключенным ИИ. Три секрета передаются Wrangler через stdin, затем включается ИИ. У каждого демо собственные пароль и секрет сессии; используется прежний общий BudgetGuard в `anete-support-demo`. Основной Worker и пять прежних клиентских Workers не развёртываются, миграций и новых бюджетных пространств нет.

После проверки ревизий запускается ранее подготовленный live-runner без повторного ввода пяти демопаролей. Только скрытый ключ OpenAI при необходимости и локальный вход Cloudflare требуют действий пользователя.

## Постоянные файлы

Новая партия хранится в `%USERPROFILE%\Lomenti-private\pilot-batch-20261026`:

- `demo-passwords.json`: приватные адреса/пароли новых демо; **не отправлять в чат, GitHub или вместе с отчётом**. API-ключ и секреты сессий туда не сохраняются.
- `publication.json`: этапы публикации и признак начала партии. Содержит идентификатор аккаунта, не credentials.
- `preflight.json`: проверка адресов и ревизий после публикации.
- `pilot-live-50-<timestamp>.json`: отдельный отчёт с вымышленными тестовыми данными, ответами и диагностикой, без cookies/ключей/паролей.
- `.pilot-live-50-20261026.json`: постоянная отметка живой партии.

Путь live-отчётов теперь общий для всех свежих ZIP-копий. Повторное скачивание не начинает новую платную партию. При частичной публикации, потере ответа, исчерпании бюджета или ошибке нужно сохранить отметки и отчёт, а не удалять их и повторять команду. Автоматического восстановления платных запросов нет.

Для обычного ручного запуска `run-pilot-live.mjs` пароли по-прежнему вводятся скрыто. Автоматическое чтение строго проверенного файла включается publisher только для этой партии. Сырые ключи Cloudflare считываются локальным Wrangler в память для read-only проверки аккаунта и не печатаются/не записываются нашим скриптом.

## Проверка подготовки

Новые тесты проверяют неверный/неоднозначный аккаунт, неправильный поддомен и BudgetGuard, запрет изменения существующих Workers, фиксированные конфигурации без лимитов/секретов, уникальные пароли, постоянный путь партии, порядок выключенный Worker → секреты → включение ИИ и остановку после неуспешной загрузки секретов. Повторных публикаций или paid retries при отказе нет.

Полный Node-набор прошёл после этих изменений. Проверки publisher и live-runner выполнялись с имитацией CLI/сети, без публикаций и OpenAI. PowerShell-оболочка проверена статически, в том числе на ASCII и отсутствие изменения ExecutionPolicy; фактический запуск на Windows пользователя ещё не выполнялся и здесь не заявляется успешным.

Команда пользователю должна скачивать bootstrap по конкретному коммиту и проверять SHA-256 перед исполнением. Нельзя использовать плавающий `main` или автоматически продолжать после ошибки. Если политика организации запрещает выполнение скрипта, её не следует отключать.
